# 神剑的使臣：高程与 OOP 作业助手

## 确认课程和限制

从用户说明及当次材料确认课程模式：高程用 `gaocheng`，OOP 用 `oop`。不因 C++ 文件、目录名称或扩展已安装而推定为 OOP；课程不明确时保持本地验证。Linux SSH 验证仅适用于已确认的 OOP 任务，具体操作时再读 [references/oop-linux.md](references/oop-linux.md)。

先阅读当次 PPT 或其 PDF、题目说明和源程序框架，再编写或修改提交程序。逐题记录材料文件和页码、提交文件名、语言、函数签名、框架和预置数据、允许及禁止的知识点、变量类型和数量、数组访问方式、行数、输入输出、编码和编译要求。

限制以当次材料和用户明确要求为依据。上一章禁止指针不影响本章明确要求使用指针；也不能把本章允许的知识点自动推广到后续章节。只对影响实现且无法从材料确定的信息询问用户。公共约定见 [REQUIREMENTS.md](REQUIREMENTS.md)。

框架中的具体限制补充当次公共要求。材料冲突时记录并核实；demo 用于确定实际输入输出，不用于绕过指定知识点、变量数量和算法要求。

## 实现与验证

逐题实现、编译、对拍并复核，再继续下一题。

1. 按已确认限制设计程序。默认将课程源程序保存为 GBK，大括号独占一行、控制体保留大括号、四空格缩进；当次明确要求优先。不通过合并语句逃避行数限制。
2. 高程使用题目要求的本地编译器，例如 MSVC、Dev/MinGW，不调用 Linux SSH 插件。OOP 可使用 SJOOP Assistant 的 MSVC、MinGW、Linux 目标，Linux 必须通过课程模式检查。调用 [scripts/sjoop_bridge.cjs](scripts/sjoop_bridge.cjs) 时明确记录 `course` 和所选目标；只有实际运行的目标可报告结果。
3. 每题提供相应 Python 测试集，复用 [scripts/demo_compare.py](scripts/demo_compare.py)。正常值、边界、题目要求的错误输入和固定种子随机数据按题目选择；固定数据题完整比对原始预置输出，额外算法试验不能改动最终数据。命令和格式见 [scripts/README.md](scripts/README.md)。
4. 捕获程序及 demo 的原始 stdout/stderr、退出码和超时。按本次要求使用真实比较器；`--trim right` 仅忽略行尾 ASCII 空格和 Tab，保留行首、行中、空行、标点、数字、顺序和换行。扩展内置判定不足时，另行严格对拍。
5. 失败时定位具体输入和首个差异，修正后重新编译复测。复核真实编译日志是否零错误、零警告，以及源码的编码、变量数量、访问形式和行数限制。

## 交付

只交付用户指定文件。测试脚本、输入、编译产物、日志及文档渲染图放在独立工作目录，不混入只允许交源程序的目录。未运行、连接失败和编译失败不能记为通过。环境受阻时报告具体目标、错误及已完成部分。
